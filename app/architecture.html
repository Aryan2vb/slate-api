Slate API · FastAPI · PostgreSQL

Architecture and processing design

Slate is a notepad-first meeting companion. The client records audio in resilient chunks while a user writes timestamped notes; after recording ends, a background pipeline transcribes the complete recording, suggests speakers, and creates evidence-grounded notes.

High-level design

System context

Large audio bypasses the API server. The API issues a signed storage URL; the client uploads each chunk directly, then confirms it. Slow provider work is queued in PostgreSQL and performed by a worker.

Recording and processing sequence

Deferred pipeline
Important behaviorUploading or confirming a chunk does not transcribe it. The pipeline starts only when the client calls POST /meetings/{meeting_id}/finish, at which point every uploaded chunk is assembled and transcribed together.
sequenceDiagram
  autonumber
  participant C as Client
  participant A as Slate API
  participant O as Object storage
  participant D as PostgreSQL
  participant W as Job worker
  participant F as FFmpeg
  participant S as STT provider
  participant L as LLM provider

  loop Each audio chunk while recording
    C->>A: Register chunk (sequence, MIME type, size)
    A->>D: Save pending chunk metadata
    A-->>C: Signed upload URL
    C->>O: Upload chunk directly
    C->>A: Confirm chunk uploaded
    A->>D: Mark chunk uploaded
  end
  Note over C,W: No transcription or analysis is triggered here.
  C->>A: Finish recording
  A->>D: Set processing; enqueue transcribe job
  A-->>C: 202 Accepted
  W->>D: Claim job; read all uploaded chunks
  W->>O: Download all chunks
  W->>F: Concatenate and normalize audio
  W->>S: Transcribe assembled audio with diarization
  S-->>W: Transcript segments and languages
  W->>D: Save transcript; enqueue speakers job
  W->>L: Suggest speaker names
  W->>D: Save speakers; enqueue enhancement job
  W->>L: Create grounded enhanced notes
  W->>D: Save notes; meeting ready
  W->>O: Delete source chunks (keep an optional expiring playback copy)
  1. Capture: chunks are individually retryable, with a unique sequence number per meeting.
  2. Finalize: finish atomically moves the meeting to processing and queues transcription.
  3. Transcribe: the worker concatenates all confirmed chunks before making one STT request.
  4. Enrich: speaker naming precedes note enhancement; speaker failure does not prevent notes.
  5. Retain or delete: source chunks are deleted after the transcript is safely persisted; an assembled playback copy is optional and expires.

Meeting and job state

Lifecycle
stateDiagram-v2
  [*] --> draft
  draft --> recording: first chunk registered
  recording --> processing: finish with uploaded audio
  processing --> ready: enhance job succeeds
  processing --> failed: non-retryable or exhausted job failure
  ready --> processing: explicit reprocess

Pipeline order

transcribe → speakers → enhance. Each completed stage enqueues the next stage; it is not a fan-out workflow.

Visible stage

The meeting API derives a user-facing stage from the active job: transcribing, identifying speakers, enhancing, ready, or failed.

Retries

Retryable provider and unexpected errors use bounded exponential backoff. Stale running jobs are reclaimed by the worker.

Reliability, security, and privacy

Operational design

Safe concurrency

Jobs are claimed through PostgreSQL locking; unique constraints protect chunk sequence numbers and active shares. Finish and enqueue are idempotent.

Provider isolation

Downloads, audio assembly, STT, and LLM calls run outside database transactions, so the system does not hold row locks while waiting on providers.

Ownership checks

Service and repository reads are scoped to the authenticated user. Missing and foreign-owned resources are treated alike.

Privacy by default

Chunks are removed after transcription succeeds. Playback retention is configurable; expired retained recordings are purged by the worker.

Grounded AI output

Generated notes are validated and post-processed so AI additions reference real transcript evidence while user notes remain unchanged.

Graceful degradation

If speaker suggestion fails, enhancement continues with generic speaker labels. A failure to retain playback audio does not undo a completed transcript.
